# recorder —— 录制回放

录下人工操作，把"点哪里"变成可运行的步骤。

- 入口类：`com.autotapper.plugin.recorder.RecorderPlugin`
- 步骤类型：`recorder.record`（录制操作）
- 需要的能力：`OVERLAY`（录制遮层）、`ACCESSIBILITY`（录到的点击最终由宿主注入下发）
- 状态：**可用的最小版本**。装了之后「步骤」里会多一种「录制操作」，
  执行时宿主拉起全屏透明遮层，用户点屏幕记位置、点顶部「结束」交回。

## 它做什么

1. 执行时先问宿主的 `RecordApi.isSupported()`：没有悬浮窗权限直接 `Fail("需要悬浮窗权限才能录制")`；
2. 拉起遮层录制，最多 `maxSeconds` 秒（10–300，默认 60），到点或点「结束」自动收摊；
3. 把录到的**点击**转成 `core.tap` 风格的步骤 JSON（`x`、`y`、`durationMs` 用录到的按住时长）；
4. **滑动一律跳过**，并在日志里逐条写明"滑动这一条没有对应内置步骤，已跳过（起点 → 终点，时长）"。
   这个版本没有等价的 (x, y, durationMs) 表达，硬凑成三次点击会让回放和用户录的完全不是一回事；
5. 把点击步骤写进插件自己的 prefs（key `lastRecorded`，值是一个步骤 JSON 数组，
   字段与宿主 `StepJson` 的 `core.tap` 编码对齐），并在日志里说清"共 N 条，已保存到插件配置；
   请到主程序「规则」页把它们加进去（当前版本还没有一键导入）"。

## 诚实边界

- **没有自动写规则**：插件没有写规则的权限（规则文件归宿主的 `RuleStore` 管），
  所以只"录好 + 存起来 + 告诉用户去哪加"，不会假装已经改过规则。
- **录制时下层应用不会响应**：遮层必须拿到触摸才能记坐标，所以录到的是"你点的位置"，
  不是"应用对这次点击的反应"。因此录制时最好对着场景慢慢点，别指望边录边操作。
- **旋转/深浅色切换会提前结束录制**：重建悬浮窗口时会把已录到的照常交回，不会悄悄丢掉。
